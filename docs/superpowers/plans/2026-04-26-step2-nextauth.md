# Step 2: NextAuth.js (Google + GitHub OAuth) Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install Auth.js v5, wire Google and GitHub OAuth providers via the Prisma adapter, create a custom sign-in page, and protect dashboard/analytics/settings routes with middleware. Step is complete when `pnpm tsc --noEmit` passes, `pnpm build` passes, `/signin` renders provider buttons, and navigating to `/dashboard` without a session redirects to `/signin`.

**Architecture:** Split config — `auth.config.ts` (Edge-safe, imported by middleware) + `auth.ts` (Node.js, includes PrismaAdapter). Database session strategy. Explicit middleware matcher for `/dashboard/:path*`, `/analytics/:path*`, `/settings/:path*` only.

**Tech Stack:** next-auth@beta (Auth.js v5), @auth/prisma-adapter, pnpm 9.15, Next.js 15, React 19, TypeScript 5 strict, Tailwind CSS v4, shadcn/ui 2.x, Prisma 6, Neon Postgres

## Chunk 2: Auth.js Configuration Files

### Task 4: Create auth.config.ts (Edge-safe)

- [ ] **Step 1: Create `web/auth.config.ts`**

```typescript
import type { NextAuthConfig } from "next-auth"
import Google from "next-auth/providers/google"
import GitHub from "next-auth/providers/github"

export const authConfig = {
  providers: [Google, GitHub],
  pages: {
    signIn: "/signin",
  },
  callbacks: {
    authorized({ auth }) {
      return !!auth
    },
  },
} satisfies NextAuthConfig
```

This file must not import `@prisma/client`, `@auth/prisma-adapter`, or any Node.js-only module.

---

### Task 5: Create auth.ts (full config with adapter)

- [ ] **Step 1: Create `web/auth.ts`**

```typescript
import NextAuth from "next-auth"
import { PrismaAdapter } from "@auth/prisma-adapter"
import { prisma } from "@/lib/prisma"
import { authConfig } from "@/auth.config"

export const { handlers, auth, signIn, signOut } = NextAuth({
  ...authConfig,
  adapter: PrismaAdapter(prisma),
  session: { strategy: "database" },
})
```

`handlers` goes to the route handler. `auth` is used in server components. `signIn`/`signOut` are server actions for UI.

### Task 7: Create middleware.ts

- [ ] **Step 1: Create `web/middleware.ts`**

```typescript
import NextAuth from "next-auth"
import { authConfig } from "@/auth.config"

const { auth } = NextAuth(authConfig)
export default auth

export const config = {
  matcher: [
    "/dashboard/:path*",
    "/analytics/:path*",
    "/settings/:path*",
  ],
}
```

Middleware uses only `authConfig` — no Prisma, no adapter. Explicit matcher means only those three route prefixes are guarded.

```tsx
  Card,
  CardContent,
  CardDescription,
  CardHeader,
  CardTitle,
} from "@/components/ui/card"

export default function SignInPage() {
  return (
    <div className="flex min-h-screen items-center justify-center bg-background">
      <Card className="w-full max-w-sm">
        <CardHeader>
          <CardTitle className="text-2xl">Sign in</CardTitle>
          <CardDescription>
            Choose a provider to access Job Tracker
          </CardDescription>
        </CardHeader>
        <CardContent className="flex flex-col gap-3">
          <form
            action={async () => {
              "use server"
              await signIn("google", { redirectTo: "/dashboard" })
            }}
          >
            <Button type="submit" className="w-full">
              Continue with Google
            </Button>
          </form>
          <form
            action={async () => {
              "use server"
              await signIn("github", { redirectTo: "/dashboard" })
            }}
          >
            <Button type="submit" variant="outline" className="w-full">
              Continue with GitHub
            </Button>
          </form>
        </CardContent>
      </Card>
    </div>
  )
}
```

No `"use client"` directive. Inline server actions call `signIn` from `@/auth` directly.
